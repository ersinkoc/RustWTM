# RustWTM 0.26.2 release review

This patch adds an opt-in Windows Task Manager replacement and fixes four
reproduced daily-use defects. The integration is disabled by default. Enable it
from Settings → This window → Windows Task Manager in an elevated, protected
installation. See [Task Manager integration](task-manager.md) for recovery.

## Reproduced fixes

- Valid quoted or omitted TOML mode keys no longer discard Monitor/Protect
  clicks; structural editing preserves comments and unrelated rule strings.
- Background launch reveals the window when the shell cannot create its tray
  icon, preserving an accessible window.
- Process/app context menus keep their original target through live sorting;
  a reused PID cannot inherit an old process menu.
- Port context menus keep their listener through row insertion and refresh;
  protocol, owning PID or creation-time changes invalidate stale menus.

Each defect was reproduced before its fix with an unaffected control and a
retained executable proof. Independent edge-case verifiers passed three times.
Permanent headless GUI regressions exercise the real views and capture intents
instead of affecting the developer's real processes, services or connections.

## Integration and release gates

The fixed GUI command isolates Windows-forwarded Task Manager arguments.
Registration requires elevation and an administrator-controlled executable;
foreign registrations and image filters are preserved. Tests use scratch HKCU
keys locally. Full uninstall removes only the owned redirect before deleting
binaries, and cleanup errors stop removal.

The hosted Windows CI gate exercises protected installation, real IFEO launch,
visible/default startup despite forwarded arguments, existing-instance reuse,
explicit restore and uninstall cleanup. A separate VM tests upgrade from the
pinned baseline, repair, rejected downgrade and data/registration retention.
These installer and global-registry checks must never run on a developer PC.
Launching Task Manager verifies the redirected launch path; this is separate
from injecting a physical Ctrl+Shift+Esc keypress.

Release certification requires format, Clippy, private-item rustdoc, complete
workspace tests and locked release builds, followed by exact-commit hosted CI.
Publication also requires downloadable ZIP/MSI checksums, binary version smokes
and provenance verification against the tagged source and release workflow.
Local native TCP assertions can fail on this host: independent native API
checks previously reproduced invalid TCP state results outside RustWTM. The
assertions remain intact; hosted tests must pass before publication.

No real resource-exhaustion proof was run. Physical fan control and the
developer machine's live shortcut association are not part of this evidence.
