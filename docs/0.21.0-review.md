# RustWTM 0.21.0 release review

Review date: 2026-10-26. Starting revision: `8f5eada` on `main`.
The only pre-existing working-tree modification was `.claude/settings.json`;
this review leaves it untouched and outside the release commit.

## Summary

Three reproduced defects were fixed, each with a permanent regression test.
The review also corrected an existing GUI test's readiness condition and
strengthened release validation. This is bounded executable evidence, not a
claim that every Windows failure path or hardware configuration was tested.

## Toolchain

Rust 1.99.1 and Rustfmt/Clippy are pinned by `rust-toolchain.toml`; the workspace
uses edition 2024 and Cargo's built-in test runner (`Cargo.toml`). The optional
hardware provider targets .NET 8 on Windows and uses the committed NuGet
lockfile (`hardware/Wtm.Hardware/Wtm.Hardware.csproj`). The repository does
not configure a race detector or sanitizer.

## Findings

| ID | Severity | Defect, impact and fix | Permanent regression |
| --- | --- | --- | --- |
| F501 | Medium | A literal star in a command line consumed the pattern's wildcard without creating a backtracking point. `*vitest*` incorrectly rejected `* node vitest`. Recognize wildcard tokens before comparing literal input. | `glob::tests::star_in_the_input_does_not_consume_the_patterns_wildcard` |
| F502 | Medium | A panicking IPC client skipped its connection-quota decrement, permanently reducing available slots. A slot now has an RAII owner that releases it on return, unwind, dropped work and failed spawn. | `ipc_server::tests::a_panicking_client_gives_its_slot_back` |
| F503 | High | Broad kill/suspend configuration treated the presence of any command-line filter as a restriction. An empty or stars-only filter could therefore bypass the guard against ending every program. Both rule and kill-list validation now recognize those unrestricted filters. | `rules::tests::match_all_command_lines_do_not_bypass_end_guards` |

F503 intentionally rejects configurations that used vacuous filters to bypass
the existing match-all safety check. Narrow image names and real command-line
restrictions remain valid. No IPC or persisted-data format changed.

The original proofs failed on their contract assertions with passing controls.
After patching, each original proof reports `PROBLEM NOT REPRODUCED`. Each
verifier passed three times. F501 additionally matched an independent recursive
reference across 116281 bounded pattern/input pairs. F502 uses channels to
gate the panic and joins the worker before asserting cleanup; it creates one
worker, without exhausting threads, memory, handles or other host resources.
F503 only parses configuration and never changes a real process.

## Baseline and test reliability

The unmodified baseline workspace run failed
`app::tests::full_app_navigates_every_tab`: the GUI received a cached service
snapshot from before the test process started. The test waited for any
snapshot, then could not find its own process row. An isolated rerun passed.
The readiness condition now waits for the PID that the test actually selects;
the selection, confirmation and cancellation assertions remain intact.

## Release hardening

- `scripts/ci/verify-release.ps1` checks a final release tag against the Rust
  workspace version, hardware provider version and dated, nonempty changelog.
  Validation exercises valid identity, mismatched versions, malformed tags,
  prereleases, leading zeros and missing release notes.
- The tag-triggered release workflow now gates publication on format, Clippy
  and documentation checks as well as workspace tests and release builds.
  Cargo dependency resolution is locked for those release commands.
- Release instructions cover both ZIP and MSI publication, digest verification
  and downloaded-binary smoke checks, and keep machine-changing checks on VMs.

The counted local passes include test bodies that return early when their
machine-changing environment gates are disabled. SCM install/uninstall,
firewall and IFEO mutation are therefore **NOT RUN locally**; their real
execution belongs to hosted CI's disposable Windows machines. Ignored tests
include timing harnesses, asset regeneration, system-drive scanning and live
external API checks. No test was disabled or weakened for this release.

Release compilation, hosted CI, publication and downloaded-asset verification
are separate gates; their final status accompanies the release hand-off.

## Boundaries and remaining validation

- Physical fan writes, fan recovery after provider/driver failure, and actual
  CPU frequency changes were not exercised. Fake-control tests do not certify
  firmware behavior.
- Hybrid and multi-processor-group hardware need representative devices before
  extending support claims. See [CPU controls](cpu-controls.md) and
  [hardware validation](hardware.md).
- No certificate-backed code signing was added. Digest verification checks
  artifact integrity against the published checksums.
- The read-only architecture pass also examined process identity/control and
  trees, IPC framing, app budgets, resource reservations, history, cooling,
  provider leases, update downloading and installer boundaries. No additional
  defect is claimed without an executable reproduction.
