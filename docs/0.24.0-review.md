# RustWTM 0.24.0 release review

Version 0.24.0 adds a read-only Docker container monitor, Overview summary and
five-language container UI. Configuration, service protocol 15 and registry
dependency versions remain unchanged. Docker remains optional.

## Implementation

- `wtm-sys::pipe_http` implements local, GET-only named-pipe HTTP with one
  deadline, byte caps, identification-level security and overlapped I/O.
  Cancellation is drained before borrowed buffers, events and handles are freed.
- `wtm-core::docker` resolves the interactive user's active Docker context,
  negotiates the Engine API, decodes HTTP/chunked/multiplexed logs, samples
  counters and keeps bounded histories. Source samples, first readings, resets,
  missing counters and observation gaps are distinguished from real zero usage.
- A separate lazy GUI worker reads Docker independently of process sampling.
  Its signal channel is bounded; the latest selection replaces older requests.
  Docker I/O never holds the process-data mutex. Shutdown replies are discarded.
- Containers can be searched by name, image, ID or Compose project, filtered by
  project/state and sorted. Details show resources, trends, ports, health,
  creation/start time, restart count and the last 200 log lines. Logs can be
  selected/copied. Old detail replies cannot appear under a different selection.
- Overview links to the page and shows container counts and the busiest fresh
  samples. Compact layouts retain a visible selected-container header. New
  controls are translated into Turkish, German, French and Spanish.
- The Docker guide is included in portable/MSI packaging and both hosted
  installation lifecycle checks.

See [the Docker guide](docker.md) for exact connection precedence, metric
semantics and resource limits. The client supports local Windows named-pipe
contexts; TCP, SSH, Unix-socket and remote-pipe endpoints are explicitly outside
this release. No Docker CLI polling, mutation endpoints or privileged service
proxy is added. No new Rust dependency is introduced.

## Safety and verification design

Repository agent rules were read first. Existing developer configuration
changes are preserved and excluded from the release changes.

Tests run on the developer's Windows PC with two Cargo jobs and two ordinary
test threads. Native timeout/error checks use small private pipes, one gated
silent peer and bounded responses. Statistics, context resolution, failures,
counter resets, fairness and list limits use synthetic fixtures. A gated Docker
worker test proves that process data remains accessible during a blocked read
and that a reply after shutdown is not published. No exhaustion proof is used.

The native adapter, core and GUI add eighteen ordinary test cases plus one
opt-in live test. They cover framing, cancellation, endpoint restrictions,
context precedence without changing global environment variables, metrics,
cache/missing/reset boundaries, bounded list decoding, logs, Windows counters,
fair sampling, responsive shutdown, filters, keyboard interaction, clipboard,
stale/error data, selected identity, compact layout and Overview navigation.

## Live boundary

The opt-in local test connected to Docker Engine 29.9.2 through Docker Desktop and the active
`desktop-linux` context and listed 55 existing containers. A second sample
verified available CPU and memory, matching detail identity and readable logs
for one existing running container. It creates, starts, stops, restarts or
modifies nothing; no private log text or workload names enter this report or
the screenshots. Windows-container metric fields are tested with synthetic
responses, not a live Windows-container engine.

Port decoding is asserted against exact IPv4 and IPv6 bindings, including the
Engine's uppercase `IP` field; the strengthened assertion was observed failing
before its serde mapping was corrected. Before/after logs are retained locally.

## Boundaries

The 0.23.0 baseline already had local native TCP-state test failures, while the
same unchanged tests passed on hosted Windows. Any remaining failures are
reported explicitly in the final workspace counts; no assertion is weakened or
test disabled for Docker. The new live test is opt-in because regular CI does
not require Docker Desktop.

Physical fan/frequency changes, real host exhaustion, certificate signing and
local installer/service replacement are outside these checks. Hosted installer
tests run on disposable Windows VMs. Container management, remote daemons and
persisted container history are outside the read-only monitoring scope.
