# RustWTM 0.23.0 release review

## Round 46 — system review

### Summary

Version 0.23.0 adds searchable, readable event diagnostics and clearer keyboard
focus in the navigation. Three reproduced findings cover failed-control retries, memory protection and
rescue-core observation timers, and IPv6 interface scopes. Six permanent tests
were added: four regressions and two event interaction tests.
Dependencies, configuration formats and IPC protocol version 15 are unchanged.

The review started from `c60bba2` (0.22.0). The only starting modification was
`.claude/settings.json`; it is excluded from the release changes. Tests and proofs
use synthetic process records, supplied clocks and small loopback sockets. Cargo
uses two build jobs and ordinary test binaries use two test threads. No resource
exhaustion, real fan writes or local installer/service replacement is performed.

### Toolchain

Rust 1.99.1 is pinned in `rust-toolchain.toml`; edition 2024 and the shared dependency
versions come from `Cargo.toml`. The runner is Cargo test, with egui_kittest 0.37.0
in `crates/wtm-gui/Cargo.toml`. Formatting uses rustfmt, linting uses Clippy with
warnings denied, and documentation uses rustdoc with warnings denied. The optional
hardware provider uses .NET 8 and its committed NuGet lockfile. No race detector
or sanitizer is configured for this run.

### Findings

#### F4601 — bug — Medium — protection timers survive an enable transition

- Location: `MemoryGuard::set_config` and `RescueCore::set_config` in
  `crates/wtm-policy/src/memory_guard.rs` and `reserve.rs`.
- Root cause: replacing configuration kept an observation timer when protection
  was disabled and re-enabled before the next sample. Disabled time was counted
  as sustained pressure; the governor already handled this transition correctly.
- Proof before: `.temp_files/F4601-before.log` records expected zero trims, actual
  three; expected no rescue step, actual `Some(Engage)`. The initial-pressure
  controls correctly wait for their sustain windows.
- Patch: clear observation clocks when the corresponding enable flag changes.
  Preserve trim cooldowns and engaged state so disable still releases protection.
- Verification: fresh sustain window, exact time boundary, unchanged configuration,
  retained trim cooldowns and release/re-engagement. Supplied `Instant` values
  advance time without sleeps or physical pressure.
- Permanent regressions: `reenabled_guard_requires_fresh_pressure_and_keeps_trim_cooldowns`
  and `reenabled_rescue_requires_a_fresh_overload_window`.

#### F4602 — input-handling — Medium — IPv6 endpoint scopes are discarded

- Location: TCP local/remote and UDP local decoding in `crates/wtm-sys/src/net.rs`.
- Root cause: `SocketAddr::new` built IPv6 endpoints with scope zero although
  Windows provides `dwLocalScopeId` and `dwRemoteScopeId` separately.
- Proof before: `.temp_files/F4602-before.log` records expected
  `[fe80::1234%1]:443`, actual `[fe80::1234]:443`; unscoped loopback is the control.
- Patch: use one scope-preserving IPv6 constructor for all three decode paths.
  Existing `SocketAddr` serialization already supports scopes; no wire change.
- Verification: scope zero, scopes 1 and 7, maximum scope ID, network-order port
  conversion and port zero, all through the same bounded decoding seam.
- Permanent regression: `ipv6_endpoints_preserve_interface_scopes`.

#### F4603 — bug — High — denied controls become false successes on retry

- Location: `Executor::reconcile` in `crates/wtm-service/src/executor.rs`.
- Root cause: the desired state was unconditionally recorded as applied even
  when a control call failed. The next identical request saw no state difference
  and returned success without trying again; the summary also claimed the denied
  setting was active.
- Proof before: `.temp_files/F4603-before.log` records expected a repeated cap
  refusal, actual `Ok(())`. The dry-run control logs without applying. The target
  is refused by `open_controlled` before any mutating call or job allocation.
- Patch: update each applied field only after its operation succeeds, retaining
  independent successful state if another operation fails.
- Verification: repeated CPU cap, priority, EcoQoS and suspend refusals, truthful
  managed summaries, plus the existing source-composition and rollback tests.
- Permanent regression: `failed_controls_are_retried_instead_of_reported_as_success`.

### Boundaries

The initial unmodified workspace fails `ports::tests::real_ports_can_be_read`.
An isolated retry and `.temp_files/round46-port-diagnostic.log` show a listener
with the correct address and PID but `Unknown(0)` instead of `Listen`.
PowerShell's independent `Get-NetTCPConnection` also returns an empty state for
a newly created listener. The wider suite reports the same symptom in
`net::tests::finds_own_listening_socket`. The final run also reports
`net::tests::finds_established_connections`: `FinWait1` was observed where the
test expected `Established`; it passed in the earlier complete run. Its cause
is not established, and it is reported separately rather than attributed to the
scope fix or the listener-state anomaly. No unknown-state-to-listener heuristic,
assertion weakening or test skip is introduced. Hosted Windows CI must separately
pass the unchanged native listener tests before the release is tagged.

Local tests do not enable machine-changing installer/SCM, firewall or IFEO gates;
some test bodies therefore return early. The existing 16 ignored tests include
live/timing/asset/whole-drive checks. Physical cooling, CPU frequency changes,
certificate signing and broader hardware certification are not verified here.
