# RustWTM 0.27.0 desktop experience review

This release delivers the implemented desktop improvements from the
[desktop experience plan](desktop-experience-plan.md). It does not complete
every milestone in that longer-term roadmap.

## Delivered behavior

- Resource strip, updated dark surfaces and process inspector hierarchy.
- Identity-safe live process ordering during inspection, separate from F6.
- Searchable column selection, six profiles, accessible ordering and persistence.
- Real-time-axis Performance charts with shared inspection, zoom, keyboard
  stepping, event markers and explicit missing samples.
- Focused resource views, CPU performance-tier filters and GPU engine search.
- English, Turkish, German, French and Spanish controls and responsive layouts.

See the [inspection guide](process-inspection.md),
[column layout guide](process-columns.md),
[timeline guide](performance-timeline.md) and
[resource view guide](performance-resources.md) for behavior and limits.

## Verification boundaries

Local GUI verification before versioning passed 217 tests, with two visual
tests intentionally excluded from the normal suite. The scoped serial GPU
review generated 180 Performance images in five languages, both themes and
wide/compact sizes, including actual compact scrolling/filter/search actions.

The versioned local workspace run completed with 711 passed, two failed and
17 ignored tests. The failures were `ports::tests::real_ports_can_be_read` and
`net::tests::finds_own_listening_socket`: port ownership was empty and TCP state
was `Unknown(0)` for the tests' own listening sockets. Both failures reproduced with the
retained 0.26.2 test executables on this host. No assertions were disabled or
weakened; the corresponding clean Windows CI checks remain required.

The release process also runs workspace format, Clippy, private-item rustdoc,
tests, optimized builds, hardware fake-control checks and PowerShell validation.
Hosted CI covers disposable-machine installer/service lifecycle, supported
upgrade baselines, source installation, coverage, provenance and expanded
localized screenshots including Processes. The release is verified only after
the exact source commit passes those gates and the downloaded ZIP/MSI checksums,
provenance, metadata and binary smokes pass. These are requirements, not claims
that a pending run has already passed.

No host resource exhaustion, developer-machine installer changes or physical
fan writes are part of local verification. The existing optional signing
policy is preserved; GitHub provenance does not imply an Authenticode signature.

## Remaining roadmap

Density/motion preferences, pinned process-name scrolling, group inspection,
physical device identity/history, persistent system history, file ownership
diagnosis, first-use guidance, visibility-aware polling, hardware health,
local organization and incident exports retain their open acceptance gates.
