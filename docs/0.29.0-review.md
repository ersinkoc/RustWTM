# 0.29.0 release scope

This minor release expands device diagnostics, application workspaces, history
and desktop controls. RustWTM remains an MIT-licensed oxog.net project maintained
by OXOGNET OÜ, Estonia, at rustwtm.com and github.com/rustwtm/rustwtm.

## Included

- Device selection with recent sparklines; read-only disk/NVMe health, endurance,
  temperature, spare capacity and lifetime counters; GPU engines and memory,
  network, CPU, RAM and battery telemetry. Missing readings stay unavailable.
- Current-user Store registrations and optional signed Microsoft WinGet discovery,
  reviewed exact source/ID/version updates and identity revalidation before handoff.
- Persistent bounded five-second resource/contributor history, protection-event
  correlation and reviewed diagnostic JSON copy.
- Local file/folder owner investigation via Restart Manager, with bounded scans
  and identity-safe navigation to process controls.
- Visual rule editing, pure-engine simulation, reviewed policy profiles, welcome
  guide, shortcut help and opt-in global show/hide.
- Optional numeric CPU/RAM/temperature tray icons, hidden-window refresh,
  configurable source/interval and recoverable logo visibility.
- 27 interface languages and consistent square, padded desktop surfaces.
- Native listener confirmation using exact membership in the OS listener-only
  table; unconfirmed state zero remains unknown. Allocations/retries are bounded.

## Compatibility and limits

IPC protocol 16 adds incident replay. Install GUI, CLI and service together.
The handshake refuses mismatched protocols. The MSI upgrade identity and service
name remain unchanged. Updates retain repository identity 1425760656 and paired
installer/checksum URLs, including clients following the old namespace redirect.

No automatic WinGet installation is added. Package updates require the optional
signed Microsoft module and explicit review; installer execution still needs
additional disposable-VM validation. Launch is not proof of an installed update.
Unregistered portable apps are not inventoried. File-owner results are a snapshot,
not proof that a file can be deleted. History observations do not prove causality.

Hardware and sensor support depend on providers, controllers and permissions.
No universal SATA SMART pass-through or physical cooling certification is claimed.
Native tray visibility, global shortcut interaction and additional physical device
coverage retain manual gates. See [implementation limits](product-expansion.md).

## Verification gates

Run release identity, locked format/Clippy/private docs/workspace tests, optimized
workspace build, hardware-provider self-test, script parsing and transfer-safe
discovery controls. Local tests use injected failure seams and bounded fixtures;
no host-resource exhaustion or installer mutation is permitted on developer PCs.

Exact-source hosted CI must pass the locked optimized build, service/MSI lifecycle, source installation,
coverage, visual rendering, provenance and pinned upgrade/repair/downgrade/data
retention checks. The 0.28.0 MSI is added to the existing upgrade baselines.
After the release workflow publishes, independently download ZIP/MSI and verify
checksums, GitHub asset digests, exact-source attestations, executable/MSI versions,
read-only CLI/provider smoke and identity-based update discovery.

Operational run IDs, digests and outcomes are retained under the ignored
`.temp_files/release-0.29.0/` directory. A local preview is not publication proof.
