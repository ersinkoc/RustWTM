# 0.26.1 release review

This patch release contains four reproduced correctness fixes. Public APIs,
configuration formats and dependencies remain unchanged.

## Docker response framing

A chunked reply ending in `0\r\nXX` was accepted as a complete response.
The decoder now requires the terminating empty CRLF line and complete trailer
fields. The regression covers malformed and truncated endings, valid trailers
and the ordinary no-trailer response.

## Governor exemptions

Adding a running, already throttled application to the governor exemption list
previously prevented further escalation without removing its existing limits.
The next tick now restores that governor source and removes its tracked entry.
Exact names, case-insensitive wildcards, repeated ticks, removal of the exemption
and unrelated offenders are covered by the regression.

## Failed termination

The executor previously discarded rollback information even when termination
failed and the process remained alive. It now forgets that state only after
successful termination. An owned-child regression applies Idle priority,
injects protection refusal before termination and confirms a later restore
returns the child to its original priority.

## Retrying failed rollback

A failed restore removed both its source request and, for the last source,
the complete rollback record. Repeating the restore then returned success
without undoing the earlier priority, efficiency, cap or suspension setting.
The executor now retains pending source restores and original settings,
retries them on live-process ticks or explicit source/all restores, and
clears pending state only after reconciliation succeeds. Other active sources
remain effective. A later snapshot removes exited process identities.

Deterministic refusal tests preserve the applied-state record and reject false
success on retry. Owned-child tests cover recovery through both retry paths,
with and without another source. The independent verifier passed three times;
all 15 focused executor tests passed on the versioned 0.26.1 source.

## Validation boundary

Local 0.26.1 checks passed release identity, workspace formatting, Clippy with
warnings denied, private-item rustdoc with warnings denied, the optimized
workspace build, hardware publish/self-test, signature-verification controls,
PowerShell script parsing and diff checks. Both release CLI and service report
0.26.1. The full local workspace run completed with 669 passed, 2 failed and
17 ignored; both failures are the TCP listener tests described below.

The developer host's TCP tables return inconsistent state values for owned
loopback sockets. Independent calls through GetExtendedTcpTable, GetTcpTable,
GetTcpTable2 and PowerShell reproduce the listener anomaly before RustWTM
parsing. Listener and established-connection assertions can fail locally.
Tests retain their assertions; unknown/closing rows are not relabeled as
listeners to obtain a green result. Local source validation and hosted Windows
validation are reported separately.

Release publication requires the resulting exact commit's hosted CI, including
the disposable installer/service, upgrade, visual, coverage and provenance
jobs. The tag workflow independently rebuilds the final ZIP/MSI. Published
assets require downloaded SHA-256 verification, version/read-only binary smoke,
MSI identity and GitHub provenance checks.

No real resource exhaustion, installer/service change, logon/UAC interaction,
physical hardware write or OS repair is performed on the developer host.
Hardware verification uses the provider's existing fake-control self-tests.
