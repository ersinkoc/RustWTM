# RustWTM 0.30.0 release scope and validation

## Scope

- Skippable, version-aware quick setup with draft preferences, compact review,
  direct section editing, keyboard navigation and visible retry feedback.
- Process descriptions beside executable names, matching name search/sort,
  independently selectable table separators, grouped column menus and width fitting.
- Contextual copying and identity-bound actions across data views, Startup
  search/status filters, common row density and full-width Settings surfaces.
- Native startup recovery: reject stale undersized window geometry, defer layout
  on empty native client areas and use one resource column on very narrow areas.
- Reduced interface motion includes automatic scrolling in both themes.

IPC remains protocol 16. Device providers, installed-app handoffs and policy
semantics retain their existing capabilities and limits. Update discovery still
uses repository identity 1425760656 and paired release asset/checksum URLs.

## Verification

Local validation uses bounded fixtures and injected failure seams. The native
startup failure was reproduced from its crash dump and a zero-width UI test;
saved 64x64 geometry is covered through the post-restoration window-builder hook.
GUI tests include every page returning from a zero-width frame, quick setup in
all 27 languages at 150% scale, draft commit/cancel and keyboard behavior.

Hosted Windows CI builds the optimized binaries and hardware provider, tests
fresh MSI/source installs, and verifies real GUI client dimensions after loading
a stale 64x64 window profile. Five pinned upgrade baselines now include 0.29.0,
with repair, downgrade rejection and configuration/history retention checks.
The visual job renders quick setup and retry states alongside the existing
desktop and device galleries. Installer mutation runs only in disposable VMs.

Release publication requires exact-commit CI, the release build and provenance.
Downloaded MSI/ZIP files are checked against SHA-256 sidecars, GitHub digests,
versions and source attestations. Read-only CLI/provider and updater discovery
smokes validate the downloaded payload. Signing depends on repository setup;
provenance and checksums do not imply an Authenticode signature.

Operational outcomes and asset identities are retained under the ignored
`.temp_files/release-0.30.0/` directory. These gates describe required checks;
their execution results are recorded separately.
